# ADR-001: Выделение правил подготовки карточки животного в контракт PetCardLogicContract

- Автор: Пономарёва А. С.
- Статус: принято

## Контекст

Метод `syncGeneric` в `PetSyncService` одновременно вызывает внешний API, проверяет дубликаты, выбирает название и описание карточки и сохраняет её. Правило выбора названия (первая порода или название по умолчанию) нельзя проверить отдельно от сети и репозиториев и нельзя заменить без правки сервиса.

## Рассмотренные варианты

1. Оставить логику внутри `PetSyncService`.
2. Выделить интерфейс `PetCardLogicContract` с реализациями и точку сборки `PetCardLogicProvider`.

## Решение

Выбран вариант 2. Контракт содержит операции `resolveName` и `resolveDescription`; сервис получает реализацию через `PetCardLogicProvider.get()`. Вне границы модуля остаются HTTP-запросы, проверка дубликатов и сохранение.

## Последствия

- Правило проверяется без сети и базы данных одним набором тестов для двух реализаций.
- Цена решения: дополнительные интерфейс, две реализации и поставщик; один дополнительный косвенный вызов на карточку.
- Уточнение поведения: пустое название породы и список с `null` теперь обрабатываются названием по умолчанию, раньше сохранялось `null`.

## Способ проверки

Тесты `PetCardLogicImplementationsTest` (обе реализации) и `PetSyncServiceCardLogicSubstitutionTest` (один потребитель, две реализации); существующие тесты `PetSyncServiceTest` проходят без изменений.
